Methodology and historical benchmark details

1. The Khan-safe Alphabet & Information Density

One of the most frequent questions is: "Why is DK Converter so much smaller than everything else?" A primary reason begins at the compression layer, then the encoding alphabet.

Khan Academy programs run in JavaScript (Processing.js), where binary data must be embedded inside string literals. Traditional converters use small character sets:

  • Bob Lyon's Imagenator (2014): Uses a 151-character alphabet → log2(151) ≈ 7.24 bits/character.
  • vExcess Imagenator: Uses base185 (185 characters) → log2(185) ≈ 7.53 bits/character.
  • Bob Lyon's PNG decoder format: Uses standard base64 (64 characters) → log2(64) = 6.00 bits/character. However, PNG's native DEFLATE is extremely powerful for smooth images.
  • DK Converter: Uses a Khan-safe 200-character alphabet (printable ASCII plus Latin letters, excluding quotes, backslashes, and backticks) → log2(200) ≈ 7.64 bits/character, then packs 4 bytes into 5 characters.

The size win comes from Zstandard plus PNG-style filters. The 200-symbol alphabet then stores those compressed bytes in 1.25 characters per byte, versus base64's 1.33.

2. DK Lossless DKL Engine: True Bit-Exact RGBA

Bob Lyon's shared PNG decoder already demonstrates standards-based, bit-exact PNG display with alpha. DK's lossless engine uses a compact custom payload and a smaller mode-specific renderer utility; the comparisons below keep the payload and utility counts separate.

  • Bob Lyon's Imagenator quantizes every R, G, and B channel into only 151 discrete steps and completely forces alpha to 255 (stripping transparency).
  • Imagenator 2 divides adjacent pixel deltas by a compression factor ≥ 3, introducing color shift and banding even at minimum settings.

Current DK Lossless uses a three-stage pipeline:

  1. Adaptive scanline filtering: Chooses the best PNG-style predictor for each RGBA row while preserving every source channel value.
  2. Zstandard level 19: The vendored WebAssembly compressor uses a worker when available and 4 MiB chunks in both paths, so progress can advance and Cancel can interrupt between chunks.
  3. Compact output text: The compressed bytes are encoded with the 200-symbol Khan-safe alphabet, 4 bytes per 5 characters. The generated DKL utility uses the small pure-JavaScript fzstd decoder, then reverses the row filters to reproduce exact RGBA.

3. DK Color-Capped Engine

Color capping is independent of image quality. Opaque still images below quality 100 use JPEG encoding and apply a bounded RGB quantizer after JPEG decoding. Other capped image modes use a bit-packed palette (DKC5), including lossless-quality still images and transparent or animated media. This allows a cap alongside lossy compression or by itself at quality 100.

How the automatic color limit works:
When the maximum colors field is left blank, DK Converter computes:

Target Colors = min(256, max(1, floor(Width × Height ÷ 500)))

For example, a 120×120 canvas (14,400 pixels) selects exactly 28 colors. A 200×200 canvas (40,000 pixels) selects exactly 80 colors.

Dynamic Bit-Packing:
Standard images store 32 bits per pixel (8 bits each for R, G, B, A). With DKC5:

  • An 8-color palette packs every pixel into just 3 bits.
  • A 28-color palette packs every pixel into just 5 bits.
  • An 80-color palette packs every pixel into just 7 bits.

Palette colors and tightly packed indices are joined, compressed with Zstandard level 19, and encoded with the same 200-symbol alphabet. The size depends on the image; color reduction is lossy.

GIFs and videos used to embed a fresh palette in every frame. A 256-color RGBA palette is 1,024 bytes before compression, so a 30-frame clip paid for that table about 30 times. Color-capped GIF and video now histogram every sampled frame together and store one shared palette on frame 0; later frames are palette indices only. That is the cheaper path: same bit depth, no repeated palettes, and temporally consistent colors.

Making that shared palette much larger (512 or 1,024 colors) does add hues, but it also adds a bit per pixel on every frame. Index data dominates palette data, so a bigger table usually costs characters. Raise the maximum-colors field when you want more hues; because the palette is stored once, that extra table is cheap compared with the old per-frame copy.

4. Audio Technology & Credit to SwankyMan

Special Recognition: SwankyMan

Native audio playback was historically considered impossible in Khan Academy's sandboxed Processing.js environment. We give deep gratitude and full credit to developer SwankyMan, who invented and pioneered the breakthrough method of injecting an AudioContext instance through PJSCodeInjector.applyInstance and Reflect.construct. This technique opened the door to sound on Khan Academy without external network requests.

DK Converter builds upon SwankyMan's audio technique by introducing an in-browser FFmpeg.wasm transcode pipeline:

  • Transcodes user audio locally into MP3, with each quality level from 1 to 100 using a distinct bitrate, sample rate, channel count, low-pass cutoff, and (at 1–20) encode speed.
  • At level 1, audio is squeezed to about a quarter of the previous floor: mono 8 kbps at 8 kHz, resampled 4× faster (which raises pitch), a 250 Hz low-pass, and playback at 0.25× to restore pitch. It sounds horrible on purpose so a track can still save.
  • Pairs audio synchronization with GIF frame timing for full video-with-sound playback.

7. Results and Limits

  • On the cat photo, current JPEG Q20 plus the 256-color cap is 19,619 payload characters. JPEG Q50 without a cap uses 35,699 characters; both counts are below the 451,255-character DKL payload and 515,046-character PNG data URI. Lossless DKL reconstructs every RGBA byte.
  • Lossless DKL also beats pngString on every synthetic fixture in this run, from 1.32x on the icon to 20.1x on the smooth 800×800 gradient.
  • Image quality and color capping are separate controls: opaque still images below 100 use JPEG, then optionally apply the color cap; transparent and animated media use lossy WebP before capping. Quality 100 leaves source pixels unchanged before any cap.
  • GIFs and videos share one palette when color capping is enabled across sampled frames, so the color table is stored once instead of once per frame. Uncapped animations retain RGBA frames in one Zstandard stream.

The 55,379-character universal utility remains the source template. Generated image programs include only their needed renderer and decoder: 42,674 characters for DKC5 palette data, 37,649 for lossless RGBA, 11,839 or 13,619 for uncapped or capped JPEG, and 6,259 for Pixel Art. Audio-only programs and video with embedded audio use the full utility.
